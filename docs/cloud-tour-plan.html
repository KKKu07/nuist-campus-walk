方案 v0.2 对标《网上南宁》 云游南信大 · 三维校园项目

云游南信大全校 1:1 三维还原 · 每栋楼都建、都能进

目标不降：每栋楼、每条路、每片水面都建出来，楼也能走进去。做法学《网上南宁》：先用数据和脚本把整个学校一次铺满，再一栋一栋换成精修模型。

结论先看这五条
  • 核心做法学网上南宁的先铺满、再替换：先用数据和脚本把全校每栋楼、每条路一次生成出来，然后成员认领楼栋，一栋栋换成精修模型。第一个月就能走遍全校，之后质量一直往上走。
  • 数据我们的数据比网上南宁准。它用开源地图和全球建筑数据估算；我们有无人机航拍（轮廓、高度、地形）、消防逃生图（每层布局）和实拍照片（立面）。
  • 外观每栋楼都做成干净的游戏模型，按实拍还原窗户、颜色、屋顶和招牌。航拍出的实景三维只用来量尺寸、做异形地标，不直接放进游戏。
  • 室内所有楼都能进：用消防图批量生成每层的墙、门、窗、楼梯，再按教室、宿舍、实验室等房间类型套家具；大厅、图书馆这类重点空间用 3DGS 实拍。
  • 技术路线首选和网上南宁一样做网页游戏（Three.js + Blender，代码用 Claude Code 写），手机电脑点链接就能玩。模型统一导出 GLB，以后想做 UE5 高画质版也能直接复用。

运行方式

浏览器里直接玩

Three.js 做网页 3D，Blender 做模型，AI（Claude Opus）写代码。作者在视频简介里说已经用掉 250 亿 token。

底图数据

开源数据铺底

道路、水面、绿地来自 OpenStreetMap；建筑轮廓和高度来自全球建筑数据集 3D-GloBFP；地形来自 SRTM 高程。

覆盖范围

全城铺满、分块加载

约 30.8 × 24.5 公里，切成 806 个街景分块，走到哪儿加载哪儿；远处用合并后的远景模型。

建筑

普通楼程序生成，地标单独做

普通楼用通用立面材质和店招图集；17 个地标单独建模，靠近加载全模，远处用简模。宣传视频里是干净的游戏画风，不是扫描出来的照片级模型。

工坊投稿

玩家按地块交模型

提交模型包（GLB + 摆放说明 + 实景照片），AI 先初审，人工再对照审核，通过后替换底图里的楼。

玩法

剧情、联机、载具

单人剧情一章、多人小游戏，能开车、骑共享电单车。目前 0.8 版封测，按版本号持续更新。

我们可以照搬的四点

  • 先铺满再替换：完整度靠程序生成，精细度靠逐栋替换
  • 数据驱动：楼的位置、轮廓、高度都来自数据，不靠目测
  • 分块加载 + 远近两套模型：场景再大，网页也带得动
  • 投稿制：统一的楼栋包规范，社团里谁都能认领一栋楼

我们还要多做一项：所有楼都能进去。消防逃生图正好让室内也能批量生成。

核心思路

全校先铺满，再一层层变精细

不按片区一块块做完，而是整个学校一起往上提质量。每一层做完都能发一个可玩的版本。

第一层 · 约第 1 个月 · v0.1

全覆盖白模

每栋楼按真实轮廓和高度自动生成，带楼层线和通用窗户；道路、湖、地形、树全部到位。这时已经能走遍全校。

第二层 · 第 2–4 个月 · v0.2–0.5

逐栋精修

成员认领楼栋，照着实拍做屋顶、立面、入口、招牌，做好就替换白模。同时用消防图批量生成所有楼的室内。

第三层 · 持续 · v0.6 起

地标与室内精品

所有楼精修完；地标楼加细节；大厅、阅览区、报告厅等重点空间换成 3DGS 实拍。剧情、载具、联机陆续上线。

数据

同样的思路，我们的数据更准

网上南宁要覆盖整座城市，只能用公开数据估算。一个校园的范围，我们可以全部自己实测。

生产线 · 底图与地形

一次航拍，给全校打底

  1. 飞前准备：登记、报备、铺像控点

    无人机按规定在民航局 UOM 平台实名登记；飞前在 App 里查限飞区，并向学校保卫处报备。

    在校园各处铺 6–10 个像控点（A4 打印的黑白靶标），请测绘同学用 RTK 测出坐标。之后所有数据都靠这些点对齐到同一套坐标。

    像控点坐标表 gcp.csv

  2. 全校航拍

    高度 60–100 m，网格往返正拍一遍，再斜 45° 前后左右各一遍（五向飞行）；前后重叠 80%，左右重叠 70%。每栋楼都要被斜拍到四个面，高度和屋顶靠这批照片量。选阴天或上午，影子少。

    工具无人机测绘航线 App没有航线功能就手动按网格飞

  3. 处理出三样东西

    照片和像控点导入 RealityScan（原 RealityCapture，学生个人免费，需要 NVIDIA 显卡），导出：实景三维（量尺寸用）、正射影像（描图用）、高程图（地形用）。备选：测绘学院机房的大疆智图、ContextCapture，或免费的 WebODM。

    mesh/ 分块模型 · ortho.tif · dem.tif

  4. 描全校底图，量每栋楼

    在正射影像上给每栋楼编号、描外轮廓；描道路边线、湖岸、广场、绿地和每棵大树的位置。在实景三维上量每栋楼的檐口高度，记下层数。推荐用免费的 QGIS，导出 GeoJSON。

    让 Claude Code 写脚本，从实景三维里自动量每栋楼的高度、算屋顶形状，人工抽查改错。

    buildings.geojson（楼号、轮廓、层数、高度）· roads · water · trees

  5. 批量生成地形和环境

    脚本读上面的文件，一次生成地形、路面（带路沿、斑马线）、湖面、草地；树按点位摆放，几种素材树轮换。校外远景用正射影像加低模，再加一张航拍 360° 全景当天空。

    生成器代码让 Claude Code 写。路灯、长椅、垃圾桶、雕塑拍几张照片，用混元3D、Tripo、Meshy 生成模型再修。

生产线 · 建筑外观

先全校白模，再逐栋精修

  1. 每栋楼拍立面

    每栋楼东南西北四个面各拍一组，尽量正对、避开树；再拍入口、楼名招牌、特殊构件的特写。全校楼多，按片区分给不同人，资产表上打勾。

    photos/B03/ N E S W entrance sign

  2. 批量生成白模（第一层）

    一个 Blender 脚本读 buildings.geojson，按轮廓拉高、按层数画楼层线、贴通用窗户材质、生成平屋顶或坡屋顶，全校一次出完。这就是网上南宁“程序化铺满”的做法。

    这是 AI 最该干的活：说清楚输入和输出，让 Claude Code 写脚本，你们负责测试和挑错。

    B001–Bxxx 全校白模 GLB

  3. 认领精修（第二层）

    成员在资产表上认领楼栋，以白模为起点、照片为参照，做出真实的窗户分布、墙面材质和颜色、屋顶设备、入口雨棚、楼名招牌。

    普通楼用构件库拼（几种窗户、墙面、檐口），风格统一、速度快；地标楼再加手工细节和照片贴图。

    PS 生成式填充去掉照片里的树和人；Substance 3D Sampler 或免费的 Materialize 把照片变成可平铺的墙面材质。

  4. 交楼栋包，替换白模

    每栋楼按下方“楼栋包规范”交付：近处精模、远处简模、摆放说明、对照照片。审核通过后直接替换白模，网上南宁的工坊也是这个流程。

生产线 · 建筑室内

消防图批量生成，重点空间 3DGS 实拍

每栋楼每层都贴着消防逃生图，这是全校室内布局最完整的现成资料。拿它批量生成，就能让所有楼都进得去。

  1. 收集消防图

    逐栋逐层正对着拍下消防逃生图，拍平、拍清。每栋楼再用激光测距仪量 2–3 个房间的实际尺寸，用来校准比例（消防图本身不一定按比例画）。

    floorplans/B03/F1.jpg …

  2. 描墙线

    消防图拉正后当底图，描出墙、门、窗、楼梯，标上房间类型（教室、办公、实验、宿舍、卫生间、走廊）。用楼的外轮廓和量好的房间尺寸校准比例。

    先让 AI 识别出墙线草稿，人再修；也可以让 Claude Code 做一个网页描图小工具，点几下就能描完一层，导出 JSON。

    B03_F1_plan.json

  3. 批量生成室内

    脚本读墙线文件，生成墙、门洞、窗洞、楼梯、地面和天花，再按房间类型自动摆家具：教室摆桌椅讲台，宿舍摆上床下桌。家具模板由建模组照实拍做几套，全校复用。

  4. 重点空间换成 3DGS 实拍

    大厅、图书馆阅览区、报告厅、标志性实验室，用 3D 高斯实拍替换生成的室内。流程：Postshot（或开源的 Brush）训练 → SuperSplat 清理压缩 → 网页里用 Spark（Three.js 的高斯渲染库）加载。拍摄要点见下方口诀。

  5. 进门才加载

    室内按楼、按层拆成单独文件，玩家进门才加载，出来就卸载，手机也带得动。宿舍、实验室等区域先问学校能不能公开，宿舍可以只做一间样板间。

3DGS 拍摄口诀 · 要

  • 相机用手动模式，锁定曝光、白平衡、对焦，整间不变
  • 慢慢走，一小步拍一张，相邻照片重叠七成以上
  • 沿墙走一圈朝里拍，在中间走一圈朝外拍，高处低处各补一遍
  • 开所有灯；有阳光的房间选光线稳定的时段一次拍完
  • 每间放 2–3 个标记，用卷尺量好间距，用来定比例

3DGS 拍摄口诀 · 不要

  • 拍到走动的人：选假期、清早，或请大家暂时离开
  • 对着大面积镜子、玻璃、电子屏一直拍
  • 只站在房间中间原地转圈（会缺深度，结果发糊）
  • 开手机的夜景、HDR、美颜（每张处理不一样，前后对不上）
  • 拍到一半换镜头或调焦距

生产线 · 游戏程序

网页游戏，代码交给 AI 写

  1. 搭网页框架

    Three.js 网页项目：角色行走、第一和第三人称切换、碰撞、小地图。先用正射影像和地形跑通，角色能在全校底图上走。代码全部用 Claude Code 写，网上南宁的作者也是这么做的。

  2. 分块加载 + 远近模型

    校园按网格切块：玩家附近的块加载精模，远处换简模或合并模型；贴图压缩成 KTX2，模型用 Meshopt 压缩；树、路灯、长椅这类重复物件用实例化一次画完。这是网页版能在手机上跑起来的关键。

  3. 玩法

    剧情：“新生报到”一章，领校园卡 → 找宿舍 → 吃第一顿食堂 → 上第一节课，顺路把校园逛一遍。

    载具：共享单车、电动车、校车。地图：俯视正射图，点地点快速传送。联机（后期）：同学一起逛、合影、校园定向越野小游戏。

  4. 内容

    讲解词和剧情对白让 AI 起草、同学改；配音用 AI 语音合成（如 CosyVoice）；UI 和图标由设计同学出图。

  5. 发布与迭代

    网页版需要服务器和域名，国内服务器要做 ICP 备案，可以请学校信息化部门挂在学校域名下。像网上南宁一样按版本号持续更新：v0.1 全覆盖，v0.2 起逐批替换精修楼。

投稿规范

楼栋包：谁做的楼都能直接替换进游戏

一栋楼交一个文件夹

B03_tushuguan/           楼号_拼音
  model_LOD0.glb         近处精模
  model_LOD1.glb         远处简模
  interior/F1.glb …      室内，按层拆
  manifest.json          楼号、位置、朝向、轮廓、层数、层高
  photos/                实景对照照片
  • 精模建议 ≤ 3 万三角面、贴图 ≤ 2K；简模 ≤ 3 千三角面。试点后按手机帧数调整。
  • 模型原点放在楼的地面中心，位置写在 manifest 里，不要把模型挪到世界坐标上。
  • Blender 里 Z 朝上，导出 GLB 时会自动转换，不要手动旋转。

审核看四件事

  • 像不像：和实景照片并排对比。
  • 准不准：叠在白模上，看位置、轮廓、高度有没有偏。
  • 超没超：面数、贴图尺寸、文件大小在不在规范内。
  • 卡不卡：放进游戏，在手机上看帧数。
后三项可以让 Claude Code 写自动检查脚本，人只看“像不像”。网上南宁也是 AI 初审、人工终审。

规范与条件

开工前先定好的规矩

统一规范（不定好，后面拼不上）

  • 同一个原点：全队约定一个点为 (0, 0, 0)，比如某个校门中心；单位米。
  • 全校楼统一编号：从正射影像上数出所有楼，B001 起编，资产表每栋一行。
  • 文件名只用英文、拼音、数字：不要中文和空格，很多 3D 软件会报错。
  • 原片永远留一份备份，处理只在副本上做。
00_ref/       消防图、立面照片、资产表
10_capture/   航拍、3DGS 原片
20_process/   实景三维、正射、高程、GeoJSON
30_blender/   白模、精修模型、构件库
40_web/       网页游戏项目

电脑与存储

  • RealityScan、Postshot 要 NVIDIA 显卡，显存 8 GB 起；全校航拍建模内存最好 64 GB。优先借学院机房电脑。
  • 写网页游戏和做建模用普通电脑就行；但要拿中低端手机测帧数，按最差的那台定规范。
  • 原片加中间文件很快到几百 GB，准备移动硬盘或 NAS。

合规

  • 无人机实名登记，飞前查空域，向学校报备。
  • 照片和高斯里拍到的人脸、车牌要打码或删掉。
  • 宿舍、实验室、机房先问学校能不能拍、能不能公开。
  • 游戏里用自己的局部坐标，不带真实经纬度；高精度测绘成果不公开上传。

下一步

这周就能开始的三件事

  1. 全校航拍一次

    先出一张全校正射影像。有了它，楼的编号、轮廓、路网都能开始描。

  2. 建资产表，给全校楼编号

    从正射图上数出所有楼，每栋一行，标上负责人，开放认领拍照。

  3. 用 Claude Code 搭网页框架

    让角色能在正射底图上走，顺便写第一版白模生成脚本，拿一栋楼试。
